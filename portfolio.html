How I Solve Problems

문제를 구조화하고, 데이터와 현장을 연결해 실행 가능한 개선안으로 설계합니다.

각 프로젝트는 같은 문제 해결 흐름으로 접근했습니다.

01 Problem Definition

무엇이 문제인지 먼저 정의합니다.

현상과 원인을 구분하고, 왜 개선이 필요한지 확인합니다.

02 Analysis

데이터와 현장을 확인합니다.

수치, 품질 변화, 사용자 행동, 운영 흐름을 확인해 문제의 원인을 구체화합니다.

03 Solution Design

실행 가능한 방법을 설계합니다.

품질기준, 운영 프로세스, Web App, 자동화 등 문제에 맞는 해결 방식을 설계합니다.

04 Impact

적용 결과와 운영 상태를 확인합니다.

실제 적용, Pilot, 제안 단계를 구분하고 결과와 개선 효과를 확인합니다.

아래 Case Study에서는 이 흐름을 실제 업무에 어떻게 적용했는지 보여드리겠습니다.

Representative Case Studies

대표 Case Study

품질 판단, 기준화, 운영 자동화가 뚜렷하게 드러나는 네 가지 사례를 같은 구조로 정리했습니다.

Case 01 · Operations Process Improvement

QC 운영 프로세스 재설계 및 자동화

분산된 QC 업무를 하나의 데이터 흐름으로 재설계해 마감 공유시간을 줄였습니다.

My Role 업무 흐름 분석, 자동화 구조 설계, 운영 적용

Tools Google Sheets · Apps Script · Slack · AI(Codex, Gemini)

Period 컬리 품질관리 운영 업무 중 수행

Status 실제 운영 적용

자동화 PPT

01 Problem

입고마감, 변질재고, 당도측정, 검품강화 보고가 각각 따로 움직였습니다. 같은 내용을 여러 파일에 다시 입력하고 Slack에 다시 공유하는 과정이 반복되면서 마감 업무에 시간이 계속 소요되고 있었습니다.

02 Analysis

업무를 파일 단위가 아니라 입력, 누적 DB, 결과 생성, Slack 공유의 흐름으로 나눠 확인했습니다. 그 결과 반복 입력과 수동 공유 단계가 주요 병목이라는 점을 확인했고, AI(Codex, Gemini)를 활용해 자동화 로직과 문서화 방향을 빠르게 정리했습니다.

03 Solution

Google Sheets, Apps Script, Slack을 연결해 데이터 입력부터 결과 생성, 공유까지 이어지는 자동화 프로세스를 설계했습니다. 사용자가 같은 내용을 다시 입력하지 않아도 운영 결과가 누적되고 공유되도록 흐름을 바꿨습니다.

04 Impact

Implemented

실제 운영에 적용해 업무 마감시간을 30분에서 20분으로 약 33% 줄였습니다. 총 7개 운영영역에 적용해 반복 입력과 수동 공유 업무를 줄였습니다.

Case 02 · Workflow Design

QR·Web App 기반 QC 루틴 업무 개선

수기로 관리하던 반복 업무를 하나의 QR과 Web App 진입점으로 묶어 현장 사용성을 높였습니다.

My Role 문제 정의, Web App 흐름 설계, Pilot 운영, 사용자 피드백 반영

Tools QR · Mobile Web App · Google Sheets · Apps Script

Period 약 2주 Pilot 운영

Status 현장 정착

01 Problem

현장에서 각종 불출대장을 수기로 작성하고 있었지만 작성 누락이 반복되었습니다. 사원들도 왜 작성해야 하는지 충분히 인지하지 못해, 단순 안내만으로는 업무가 루틴으로 정착되기 어려웠습니다.

02 Analysis

기존 작성 방식과 실제 사용자 행동을 확인했습니다. 디지털 기기에 익숙하지 않은 사용자까지 고려했을 때, 기능을 많이 넣는 것보다 쉽고 직관적인 사용 흐름이 정착에 더 중요하다고 판단했습니다.

03 Solution

QR코드로 Mobile Web App에 접속해 필요한 내용만 등록하면 기록이 Sheet에 자동 누적되는 구조를 설계했습니다. 약 2주간 Pilot을 운영하며 실제 사용자 피드백을 반영해 화면과 기능을 수정했습니다.

04 Impact

Pilot Completed

대부분의 사용자가 새로운 방식으로 업무를 수행하게 되었고, 일부 누락을 제외하면 현장에 정착되었습니다. 사용자 편의성 개선 피드백을 확보했으며, 5개 반복 업무를 Web App 기반으로 통합했습니다.

Case 03 · Product Quality Standards

상품 품질기준 개선

수박 당도 기준과 사과 최소당도 기준을 각각의 품질 판단 사례로 분리해 정리했습니다.

My Role VOC 확인, 측정 데이터 분석, 관리기준 개선안 설계

Tools VOC · 당도 측정 · 관능평가 · 기준 비교

Period 컬리 품질관리 운영 업무 중 수행

Status 관리기준 Pilot 및 기준 개선안 제안

수박 PPT사과 PPT

Watermelon

수박 당도관리기준 11 Brix 상향 제안

단맛 관련 관능 VOC를 기준 개선 과제로 보고, 수박 당도 관리기준을 11 Brix로 상향하는 방향을 검토했습니다.

VOCSensory TestQuality Standard

01 Problem

단맛 관련 관능 VOC가 반복되고 있었습니다. 단순히 “맛이 약하다”로 끝내기보다, 고객이 낮은 만족도를 느끼는 조건을 확인하고 관리기준으로 연결할 필요가 있었습니다.

02 Analysis

VOC, 당도, 관능평가 데이터를 함께 확인하고 5개 SKU 파괴당도 측정과 5점 척도 관능평가를 진행했습니다. 경쟁사와 협력사 기준도 비교해 단맛 VOC가 단순 취향 문제가 아니라 관리기준 조정으로 다룰 수 있는지 검토했습니다.

03 Solution

저당도 개체가 고객 만족도를 낮출 수 있다고 보고, 관능 VOC 해결을 위해 수박 당도관리기준을 11 Brix로 상향 관리하는 Pilot 운영 방향을 설계했습니다.

04 Impact

Pilot Proposed

수박 11 Brix 관리기준 상향 Pilot을 제안했습니다. 실제 운영 적용 전 검증 단계임을 구분해 관능 VOC 대응을 위한 관리기준 개선안으로 정리했습니다.

Apple

사과 SKU별 최소당도 관리기준 설계

DistributionVOCQuality Risk

01 Problem

평균당도는 기준 안에 있어도 저당도 개체가 섞일 수 있었습니다. 평균값만으로는 고객이 실제로 받는 품질 편차와 저당도 개체 혼입 가능성을 설명하기 어려웠습니다.

02 Analysis

SKU별 당도 분포, 표준편차, 표시당도와 실제 측정값, 기준 미달 개체 비율을 확인했습니다. 13 Brix SKU 25%, 14 Brix SKU 33.7% 기준 미달률을 통해 평균 중심 관리의 한계를 확인했습니다.

03 Solution

당도 평균 관리에서 최소값을 보증하는 관리법으로 바꾸는 개선안을 설계했습니다. SKU별 특성과 측정 분포를 기준으로 최소당도 관리기준을 제안했습니다.

04 Impact

Standard Proposal

SKU별 최소당도 관리기준을 제안했습니다. 실제 고객 경험의 편차를 줄이기 위해 평균이 아니라 최소 수준을 기준으로 보는 관리 방향을 제시했습니다.

Case 04 · PB Product Quality Improvement

PB 간편과일 판매일수 재설정

반복되는 품질저하를 확인하고, 판매 가능 기간을 그대로 둘 수 있는지 검증했습니다.

My Role 품질 변화 확인, 비교 상품 검토, 판매일수 Pilot 운영안 제안

Tools 품질 관찰 · 비교 검증 · VOC · 관능평가

Period 컬리 품질관리 운영 업무 중 수행

Status 판매일수 단축 Pilot 제안

PB 간편과일 PPT

01 Problem

일부 PB 간편과일 SKU에서 변색, 상함, 드립, 맛 저하가 반복 확인되었습니다. 판매일수가 상품 상태 변화 속도와 맞는지 다시 검토해야 했습니다.

02 Analysis

상품별 품질 변화와 외관, 맛, 드립 이슈를 확인하고 PB 상품과 Dole 상품의 품질 편차를 비교했습니다. 1차 확인 후 일부 상품은 재검을 통해 품질저하의 반복성을 다시 확인했습니다.

03 Solution

품질 저하가 반복된 일부 SKU는 판매마감일수를 현행 대비 1일 단축하는 Pilot 운영안을 설계했습니다. 이후 VOC와 관능평가를 통해 최종 판매일수를 확정하는 관리 방향까지 제시했습니다.

04 Impact

Pilot Proposed

판매일수 단축 운영안을 제안했습니다. 실제 적용 결과가 아닌 Pilot 제안 단계로 구분하고, 검증 이후 운영 적용을 검토하는 방식으로 정리했습니다.
