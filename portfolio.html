How I Solve Problems

문제는 네 단계로 접근했습니다.

문제 정의 → 원인 분석 → 해결안 설계 → 결과 확인의 순서로 접근합니다.

01 Problem

무엇이 문제인가

현상과 원인을 구분하고, 왜 지금 개선해야 하는지 정의합니다.

02 Analysis

왜 발생했는가

데이터, 업무 흐름, 사용자 행동, 공정 조건을 확인해 원인을 좁힙니다.

03 Solution

어떻게 바꿀 것인가

기준, 프로세스, 자동화, 운영 방식 중 문제에 맞는 해결안을 설계합니다.

04 Impact

무엇이 달라졌는가

시간, 오류, 사용자 정착, 품질 변화 등 실제 운영에서의 결과를 확인합니다.

Case 01 · Process Improvement / Automation

집중검품리스트 생성 프로세스 자동화

집중검품리스트의 반복 휴먼에러를 없애기 위해 생성 과정을 Apps Script로 자동화했습니다.

Role 문제 정의 · 프로세스 설계 · 자동화 구현 Tools Google Sheets · Apps Script Status 실제 운영 적용
01 Problem

휴먼에러가 업무 지장으로 이어졌습니다.

집중검품 대상 리스트를 수동으로 생성하는 과정에서 누락·오입력 가능성이 있었고, 오류가 실제 현장 업무 분배와 준비 과정에 영향을 줄 수 있었습니다.

02 Analysis

오류가 생기는 수동 단계를 분리했습니다.

상품 매칭, 대상 제외, 구분·정렬 등 사람이 반복 판단하던 단계를 나누어 확인하고 자동화할 수 있는 규칙과 예외 조건을 정리했습니다.

03 Solution

Apps Script 기반 자동 생성 구조를 설계했습니다.

반복 판단을 코드화하고 리스트 생성 과정을 자동화해 사람이 직접 수정·복사하는 단계를 최소화했습니다.

04 Impact

오류를 없애고 제작시간도 줄였습니다.

기존 휴먼에러를 제거하고 리스트 제작시간을 30% 이상 단축해 현장 업무 준비의 안정성과 속도를 함께 개선했습니다.

Implemented
Human Error ↓ · Time 30%+ ↓

사람이 반복적으로 판단하던 단계를 자동화해
정확성과 업무 준비 속도를 함께 개선

Case 02 · User-Centered Workflow Design

QR·Web App 기반 반복 업무 개선

반복되는 작성 누락을 사용자 편의성 문제로 보고, QR·Web App 기반 업무 흐름으로 재설계했습니다.

Role 문제 정의 · Web App 흐름 설계 · Pilot · 사용자 피드백 반영 Tools QR · Web App · Google Sheets · Apps Script Status Pilot 완료 · 현장 정착
01 Problem

작성 누락이 반복됐습니다.

수기 대장은 작성이 자주 누락됐고, 사용자는 왜 작성해야 하는지 충분히 인지하지 못해 반복 안내만으로는 루틴화가 어려웠습니다.

02 Analysis

사용자의 진입장벽이 핵심이라고 봤습니다.

디지털 기기에 익숙하지 않은 사용자까지 고려했을 때 기능을 많이 넣는 것보다 짧고 직관적인 입력 흐름이 정착에 더 중요하다고 판단했습니다.

03 Solution

QR → Web App → Sheet 흐름을 만들었습니다.

QR로 접속해 필요한 내용만 입력하면 자동 누적되도록 구성하고, 약 2주 Pilot 동안 피드백을 받아 화면과 기능을 수정했습니다.

04 Impact

사용자가 실제로 쓰는 방식으로 정착했습니다.

일부 누락을 제외하면 대부분의 사용자가 새로운 방식을 사용하게 되었고, 기존보다 편리하다는 피드백을 확보했습니다. 5개 반복 업무를 하나의 진입점으로 통합했습니다.

Pilot Completed
2주 Pilot · 5개 업무 통합

기능보다 사용성을 우선해
실제 현장에 정착되는 업무 흐름으로 개선

Case 03 · Data-Based Standard Design

품질 데이터를 관리기준으로 연결

VOC·당도·관능·측정 데이터를 분석해 기존 품질 판단의 한계를 확인하고 관리기준 개선안으로 연결했습니다.

Role VOC 확인 · 측정 분석 · 기준 개선안 설계 Scope 수박 당도기준 · 사과 최소당도 기준 Status Pilot / 기준 개선안 제안
01 Problem

기존 기준만으로 고객 경험을 설명하기 어려웠습니다.

수박은 단맛 관련 VOC가 반복됐고, 사과는 평균당도가 기준을 충족해도 저당도 개체가 섞여 고객이 받는 품질 편차를 관리하기 어려웠습니다.

02 Analysis

VOC와 측정값의 분포를 함께 봤습니다.

수박은 VOC·당도·관능평가와 경쟁사 기준을 비교했고, 사과는 SKU별 당도 분포·표준편차·기준 미달률을 확인해 평균 중심 관리의 한계를 분석했습니다.

03 Solution

문제에 맞는 관리기준을 새로 설계했습니다.

수박은 11 Brix 관리기준 Pilot을, 사과는 평균이 아닌 최소값을 보증하는 SKU별 최소당도 관리방식을 개선안으로 제안했습니다.

04 Impact

검사 데이터를 ‘판단 기준’으로 전환했습니다.

측정 결과를 단순 보고하는 데서 벗어나 고객 경험과 품질 편차를 줄이기 위한 관리기준 개선안으로 연결했습니다.

Proposal / Pilot
Data → Standard

검사·VOC 데이터를 분석해
운영에서 사용할 수 있는 품질 판단 기준으로 전환
